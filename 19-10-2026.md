# Lancer supportdesk en local (npm)

## Symptômes

- `npm start` échoue avec `Error: Could not locate the bindings file`
  (module natif, probablement `better-sqlite3`, qui n'a pas de binaire pour Node 24)
- Après un `npm ci` raté : `Cannot find module 'express'`
  (`node_modules` vide car l'installation avait échoué)

## Cause

La machine tournait sous **Node v24**, trop récent pour les modules natifs du projet.
Le flag `--build-from-source` n'existe pas pour `npm ci` (erreur `EUNKNOWNCONFIG`),
donc l'installation n'a rien installé.

## Solution : utiliser Node 22 (LTS) via nvm

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# IMPORTANT : fermer puis rouvrir le terminal pour que nvm soit actif
nvm install 22
nvm use 22
node -v   # doit afficher v22.x

cd ~/Desktop/SentinelX/B-SPE-322-MPL-3-1-sentinelx-1/supportdesk
rm -rf node_modules
npm ci
npm start
```

## Points à retenir

- Après l'installation de nvm, **redémarrer le terminal** : sinon `nvm` n'est pas
  chargé et `node` reste en v24.
- Toujours vérifier `node -v` avant `npm ci`.
- Les modules natifs sont sensibles à la version de Node : privilégier une version LTS (20 ou 22).
- Pour le docker-compose final, utiliser une image `node:22` pour que le setup
  soit identique pour toute l'équipe.

## Non nécessaire au final

`build-essential`, `python3`, `make`, `g++` (installés pendant le debug) : utiles
seulement si une compilation locale est requise.
